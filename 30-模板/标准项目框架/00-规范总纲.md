# 00-规范总纲

> 本工具箱全部工程规范的唯一出处。模板骨架是"怎么写"，本文件是"为什么这么写"和"必须做到什么"。
> 每条规范标注实战出处，改规范前先读出处。

---

## 一、分块规范

### 1.1 文件职责划分（红线）

| 文件 | 只许做什么 | 不许做什么 |
|------|-----------|-----------|
| `run.py` | 装异常钩子、启动界面 | 任何业务逻辑 |
| `core_engine.py` | 全部业务逻辑，只通过 callback 对外通信 | `import webview / PySimpleGUI / tkinter` |
| `excel_io.py` | 一切 Excel/CSV 读写（走公共库 + 本规范第 3 章硬保护） | 业务判断 |
| `web/` | 展示与收参 | 业务逻辑（只允许调 Api） |
| `config.py` | 常量、关键词表、阈值、映射表 | 逻辑代码 |

> 出处：项目3 的 callback 模式（引擎零 UI 依赖可单测）；项目10 的模块化目录（config/exceptions/extractor/merger/validator/exporter 一文件一职责）；项目18/27 的 webui_main 只做桥接。

### 1.2 体量红线

- 单文件超过 **400 行**必须拆分（出处：项目7 单文件 2944 行 = 反模式标杆，不可维护）
- 引擎与界面**物理分离**：引擎文件里出现界面 import 即违规

### 1.3 纯函数优先

同样输入 → 同样输出。不碰全局变量、不在引擎里记界面状态。需要"记住"的东西（上次用的目录、筛选条件）一律存 `data\*.json`，由界面层读写（出处：项目18 的 saved_conditions.json）。

## 二、注释规范（中文学习级）

### 2.1 文件头五要素

```python
"""多Excel合并汇总 — 把多个Excel的同结构sheet合并成一个汇总表
输入:  一个文件夹路径（内含若干 .xlsx/.xls/.csv）
输出:  汇总表 xlsx（带来源标记列）+ 处理日志
依赖:  _common_utils（编码链）、excel_io
修改:  v0.1 2026-10-08 初版（菡）
"""
```
出处：项目2 的 changelog 实践（v3.3→v3.8 每版改了什么，排障时 priceless）。

### 2.2 函数注释三级

1. docstring 三行：干什么 / 参数 / 返回
2. **关键决策写"为什么"**，真实范例：
   ```python
   TOLERANCE = 0.01   # 容差 0.01 元：银行流水常见分位四舍五入差，低于此值报差异会全是噪音（项目5 实战）
   ```
3. 魔法数字禁止裸奔——不进 config.py 就写来源注释

> 出处：项目10 config.py（40+ 标准列名/关键词/正则全部命名外置，引擎零魔法字符串）；项目5 的"关键修正"列表；项目19 的"P1 网格口径"注释。

### 2.3 移植/迁移标注

从 VBA、旧工具、同事代码迁移来的逻辑，保留原名称注释。出处：项目23 `InsertDetailsAsText`（VBA→Python 可回查）。

## 三、工程标准（代码层硬保护）

### 3.1 每条入口必须内置

```python
# ① 异常钩子：未捕获异常自动写 tools/_logs，同事截图即可定位
# ② stderr 兜底：pythonw/GBK 环境下一个 ✅ 字符就会触发 UnicodeEncodeError 中断全流程
#    （项目23 的教训，两行一起拷）
```
骨架已在 run.py/webui_main.py 内置，**删掉即违规**。

### 3.2 Excel/CSV 读写

- 一律走 `_common_utils.read_excel_auto / read_csv_auto`（calamine 优先自动降级 + 编码探测链 utf-8-sig→gbk→gb18030→big5/cp950→latin-1 + Sniffer 分隔符）
- 病态 ETL 文件（dimension 错写漏读）用 openpyxl `reset_dimensions()`（出处：项目3）
- 长数字 ≥12 位保文本防科学计数（出处：项目26）
- 写大文件用 xlsxwriter `write_row`（出处：项目27，提速 10-50x）；样式按类型缓存（出处：项目24，20k 行 59s→10s）

### 3.3 文件写保护（两条暗桩，模板 excel_io.py 已内置）

1. **长路径**：绝对路径 >240 字符自动加 `\\?\` 前缀（出处：项目37 `_lp()`）。OneDrive 桌面 + 中文文件夹 + 深层级极易超 260 上限。
2. **原子写**：先写 `.tmp` 再 `os.replace` 替换——中途崩溃不会留下写了一半的文件毁掉同事数据（出处：项目7/37）。**覆盖已有文件前**先留 `.bak` 备份（出处：项目19/8）。

### 3.4 错误消息三要素

任何人话错误必须带：**发生了什么 + 哪个文件哪一行 + 建议怎么办**。

> 范例（出处：项目27）：`未找到金额列（当前表头：日期/摘要/借方发生额），建议：检查表头是否含"借方/贷方/金额"字样，或在 config.py 的 AMOUNT_KEYWORDS 里补充该客户的关键词`

### 3.5 界面交互标准

- 状态提示写 `<span class="status ok/err/busy">`，图标由母版自动缀 ✅❌⏳，**不许手写图标**（出处：toolbox.js 契约）
- 输出目录输入框 label 必须含「输出目录」（母版据此自动加「📁 默认」按钮）
- 运行期间禁用运行按钮防连点；完成后显示「📂 打开结果文件夹」（出处：项目27 app.js）
- 选文件一律走 `Api.choose_file()`，**禁用 `<input type=file>`**（pywebview 不注入路径）
- 能用 **Excel 中间表驱动**的流程优先于让同事学界面：程序导出清单 → 同事填 Y/N 或分类 → 程序读回执行（出处：项目2/11，非 IT 同事零学习成本）
- 耗时操作给进度：进度条 + 阶段文字（"正在读取 3/12 个工作表…"）；提供取消按钮 + 半成品自动清理（出处：项目24）

### 3.6 孤本提升规则（全工具箱最重要的流程规则）

> **任何工具在开发中解决了一个通用硬问题（长路径/原子写/新编码/新格式/超时……），必须把它提升到 `excel_io.py` 或 `_common_utils.py` 公共层，并在 `00-规范总纲.md` 登记一行。**
> 出处：本次萃取的最大教训——`_lp` 长路径解法是项目37 的孤本，其他 24 个工具都在裸奔。好实践困在单个工具里 = 全工具箱都没受益。

登记格式（追加到本文件第九章）。

## 四、打包分发规范

1. **.bat 一律 GBK 无 BOM + `chcp 936`**（cmd 窗口中文不乱码）。出处：现网全部 bat。
2. 分发 zip 生成后跑路径体检：内部最长路径 + 60 字符（OneDrive 桌面前缀）< 260，超了预警。出处：`_打包分发.ps1`。
3. 随包附《解压说明.txt》：**解压到本地短路径（如 `C:\工具箱\`），不要放 OneDrive 桌面**（同步大量小文件报错+拖慢）。出处：`_打包分发.ps1` 内嵌说明。
4. 子进程一律 `CREATE_NO_WINDOW` 或显式控制台——不许黑窗乱闪（当前全库空白项，新工具必须遵守）。
5. A 档打包：`build_exe.py`（--onefile --windowed --clean --noconfirm）。出处：项目9。

## 五、视觉规范

### 5.1 设计令牌（style.css `:root`，唯一审美入口）

| 令牌 | 值 | 用途 |
|------|----|----|
| --header-bg | #1a3a5c | 顶栏 |
| --blue | #4472C4 | 选择/浏览类按钮 |
| --green | #70AD47 | 执行/确认类按钮 |
| --orange | #C55A11 | 清空/危险类按钮 |
| --match-bg / --diff-bg / --partial-bg | #C6EFCE / #FFC7CE / #FFEB9C | 匹配/差异/部分——与 Excel 条件格式同色 |
| --bg / --card / --border | #f0f2f5 / #fff / #d9dde3 | 浅底白卡 |
| 间距 | 4 / 8 / 16 递进 | |
| 圆角 | 6（控件）/ 10（卡片）/ 16（图标） | |
| 字号 | 12 / 13 / 14 / 16 / 20 | 13 为正文基准 |

> 调审美只改令牌表，不改组件。**工具界面浅色专业风**；深色玻璃风仅属启动器门户，工具不用。

### 5.2 六个基础组件

`.card / .row / .btn（三职能色）/ .status / .stat-card / .log-box`，外加 `.direction-tip`（橙底业务规则警示条，出处：项目5 借贷方向提示）。

### 5.3 界面两形态

- **单栏卡片表单**：简单参数型工具（B 档骨架默认）
- **工作台双栏**：数据预览型工具（左：编号步骤 1-2-3-4 + 方向警示 + 统计卡 + 深色日志盒；右：结果 tab 页签）。见 `附-工作台双栏布局/`

### 5.4 微交互标准

按钮 hover 上浮 1px+阴影加深、卡片进入渐显上移 15px、状态切换 0.2s 过渡。统计数字 28px + `tabular-nums`。
